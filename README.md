# Сканер продуктов — мобильное PWA

Мобильное веб-приложение на русском языке: камера считывает EAN / UPC, серверный endpoint обращается к Open Food Facts, интерфейс показывает состав, энергоценность и **ориентировочный индекс замечаний к составу от 0 до 100**. 0 означает меньше замечаний, 100 — больше. Число **не является клинической оценкой опасности**.

## Что реально работает в MVP

- Считывание штрихкодов камерой через ZXing, поддержка вспышки на совместимых устройствах. На HTTPS / localhost требуется разрешение на камеру.
- Ручной ввод кода, запрос сведений из Open Food Facts через `/api/product`.
- Карточка товара: название, фотография (если есть в каталоге), калории и БЖУ на 100 г/мл, порция (только если указан размер), состав с выделенными словами, плюсы и минусы, ориентировочная альтернатива.
- Отдельные поля по воде. Минерализация и жёсткость не выдумываются; при отсутствии подтверждённых данных отображается «Нет данных».
- История последних 50 товаров, избранное, сравнение двух избранных, настройки аллергенов и рациона в localStorage. Эти данные сохраняются на том же устройстве, но **пока не синхронизируются**.
- Пустые состояния, скелетоны, PWA-кэш оболочки и изображений OFF, работа с ранее сохранёнными товарами в офлайне.
- Отображение низкой полноты данных нейтральным кругом «—», а не вводящей в заблуждение зелёной оценкой.
- Проверки серверной обработки фотографии и клиентских результатов ИИ включены в тесты.

**Готов к подключению этап 2:** распознавание фото упаковки и самого продукта через защищённый `/api/analyze`. Нужен платный серверный ключ `OPENAI_API_KEY`. Без него сервер возвращает понятную ошибку, не выдумывает результат. Для фото еды вместо ложной точной цифры выдаётся диапазон ккал, если модель в состоянии оценить его. Снимок отправляется только после отдельного подтверждения пользователем. Данные ИИ помечены как предположительные. Фото не сохраняются в историю; сохраняется только текстовый результат.

**Пока не подключено:** серверное хранение профиля в Supabase и синхронизация между устройствами. Миграция `supabase/migrations/001_init.sql` является заделом под следующий этап.

В `design/preview.html` приложен **статичный пример главного экрана**, полезный для просмотра оформления без запуска React. Он не является отдельным рабочим сканером.

## Быстрый запуск

Нужен Node.js 20.19+ или 22.12+.

```bash
npm install
npm run dev
```

Открыть адрес Vite, обычно `http://localhost:5173`. На телефоне камера доступна только через **HTTPS**, а не по обычному локальному IP; для удобства опубликуйте приложение на Vercel.

В режиме Vite запрос `/api/product?code=...` перенаправляется на Open Food Facts. Продакшен использует серверную функцию `api/product.ts` на Vercel.

```bash
npm run typecheck
npm run test
npm run build
npm run preview
```

## Деплой на Vercel

1. Загрузить содержимое проекта в репозиторий GitHub.
2. Import Project в Vercel, Framework Preset: `Vite`.
3. Build Command: `npm run build`, Output Directory: `dist`.
4. Развернуть проект: Vercel автоматически обработает `api/product.ts` как серверную функцию.
5. В настройках проекта добавить переменную `APP_CONTACT_URL` — действительный URL проекта или контакта для корректного User-Agent к Open Food Facts.
6. Открыть адрес по HTTPS и разрешить камеру.

Все запросы к каталогу проходят через сервер, на клиенте нет секретных ключей. В режиме разработки прокси делает такой же запрос. Serverless-функция ставит HTTP CDN-кэш, устройство хранит записи до 7 дней.

## Как устроена оценка

Локальная функция `src/lib/evaluate.ts` суммирует эвристические признаки: сахар, соль, насыщенные/трансжиры, NOVA, Nutri-Score, клетчатку, белок и размеченные добавки. Вредность отдельных добавок **не устанавливается по одному E-номеру**. Балл — продуктовая подсказка, а не медицинский диагноз; он может измениться при пополнении базы. При нехватке сведений индекс не выводится как достоверный. Используйте первоисточник и проверяйте этикетку, особенно при аллергиях.

Цель отклика 2–3 секунды не гарантируется: это зависит от камеры, подключения к сети и быстродействия Open Food Facts.

## План дальнейшего развития

**Этап 2 — сервер и интерфейс реализованы, нужны секрет и проверка в деплое.** В Vercel → Project → Settings → Environment Variables заполнить `OPENAI_API_KEY` (server-only) и опционально `OPENAI_VISION_MODEL` (по умолчанию `gpt-4.1-mini`). Не добавлять ключ в `VITE_` или в Git. Публичный сервис с платными ИИ-запросами перед широким запуском обязательно защитить авторизацией, лимитами вызовов на пользователя и расходным бюджетом. В разработке Vite проксирует только `/api/product`; для `/api/analyze` нужен Vercel dev или другой серверless-рантайм. Фото отправляются в OpenAI для анализа, если пользователь подтвердил отправку. Нельзя гарантировать ответ за 2–3 секунды.

**Этап 3** — Supabase Auth, RLS, синхронизация `users`, `scans`, `favorites`, `products_cache`, расширенные персональные предупреждения и сравнение с предложениями на основе реальных данных каталога.

## GS1 Data Matrix и «Честный ЗНАК» (v2.3)

- Камера распознаёт EAN / UPC и GS1 Data Matrix; из Data Matrix извлекается GTIN (AI 01).
- Даты **AI (17)** и **AI (15)** показываются только если присутствуют в самом коде. Дата производства — AI (11). Данные по конкретной упаковке **не помещаются в общий кэш товара**, серийный номер и криптохвост не отправляются в Open Food Facts.
- Если дат в Data Matrix нет, приложение пишет «нет данных». Срок годности EAN-13 определить нельзя.
- Расшифровка Data Matrix **не подтверждает подлинность товара, его статус или условия хранения**. Эти сведения можно проверить в официальном приложении «Честный ЗНАК» либо через разрешённый True API, который требует официального доступа.
- Добавлен опциональный адаптер **Национального каталога**: при установке серверной переменной `NATIONAL_CATALOG_API_KEY` он может подтянуть название товара и явно указанную информацию о составе в случае отсутствия записи Open Food Facts. API: `/v3/product?gtin=...`. Ключ задаётся ТОЛЬКО в Vercel Environment Variables, без префикса `VITE_`.
- Интеграцию с Национальным каталогом без действительного разрешённого ключа **нельзя считать подключённой и проверенной**. Доступ к True API и верификация кодов требуют отдельного договора/участия или интегратора. Не используйте закрытый потребительский API, нелегальные прокси либо токен кассовых проверок для стороннего сканера.
- При неизвестном составе и пищевой ценности приложение не выдумывает БЖУ и балл пользы.

Источники: [пояснение API на markirovka.ru](https://markirovka.ru/community/developers/poluchenie-informatsii-o-ki-bez-ispolzovaniya-ukep), [GS1 Application Identifiers](https://ref.gs1.org/ai/).


## Общий каталог Supabase (серверная интеграция — подключение ожидает отдельную базу)

Добавлен безопасный read-through кэш товаров из открытых каталогов.

1. Создайте **отдельный проект Supabase для skaner-produktov**; не используйте БД других проектов.
2. Примените миграции `supabase/migrations/001_init.sql`, затем `002_shared_product_cache.sql`.
3. В Vercel → Project → Settings → Environment Variables укажите только серверные переменные:
   - `SUPABASE_URL` — HTTPS-адрес API новой базы;
   - `SUPABASE_SERVICE_ROLE_KEY` — секретный ключ роли service_role (не публикуйте, не используйте `VITE_`).
4. Сделайте Redeploy. При отсутствии этих переменных сервер продолжает работать без общего кэша.

Алгоритм: чтение свежей карточки из Supabase → Open Food Facts → Национальный каталог (только при разрешённом доступе) → вручную проверенные резервные карточки → устаревшая проверенная карточка из кэша (не старше 30 дней) с явным предупреждением → ошибка с предложением фото. Положительные результаты кладутся в Supabase с TTL: OFF 48 ч, Национальный каталог 24 ч, резервные карточки 3 ч.

Общая база хранит только публичные сведения о товаре, полученные сервером из указанного источника. **Не сохраняем** пользовательские фото, содержимое Data Matrix (серийные номера/криптоданные), индивидуальные сроки годности, частные профили и вручную введённый состав. Ручные исправления остаются в локальной истории пользователя. Доступ из браузера к service_role полностью запрещён.

Сведения Open Food Facts сохраняют происхождение и должны использоваться с соблюдением условий лицензии Open Database License (ODbL), включая атрибуцию. База не является проверкой безопасности или подлинности продукта.
